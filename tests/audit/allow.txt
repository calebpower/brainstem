# tests/audit/allow.txt — the external surface brainstem is allowed to have.
#
# One line per "unit symbol", read by tools/bsaudit.sh (tier 10b) against the
# objects the compiler emitted. Adding a line here is the only way to add a
# dependency, and it is a review event: every line is a thing this program
# reaches outside itself to do.
#
# ONE FILE FOR BOTH PLATFORMS. Rows naming a unit this build did not produce
# are vacuous rather than stale -- sys_freebsd is not built on Linux -- which
# is what lets the two platforms share a single statement of the surface.
#
# Symbol names are the ones the SOURCE uses. The audit undecorates what the
# toolchain emitted first, so __fprintf_chk matches fprintf and __error
# matches errno, and it ignores the pure memory and string helpers outright
# because whether those appear at all is the compiler's choice rather than
# the program's. See normalise() in the audit for both.
#
# Note what is NOT here, and could not be added without an argument: no
# malloc, no fopen, no getenv, no setlocale, and nothing whatever for frame,
# err, op_ctl, op_time, op_rand or det. Those six units reference nothing
# outside themselves, which is the strongest single thing this file says.

# takes a literal address and this list has no resolver in it.

# ---- sys_proc.c: the process half of the seam ----
#
# This is the whole of brainstem's ability to start a program. There is no
# system(), no popen, no shell anywhere on this list and there will not be
# one: spawn takes a path and an argv and never a command line, so there is
# nothing for a quoting bug to become.
#
# fchdir is here rather than posix_spawn because there is no posix_spawnat and
# every path in this ABI resolves beneath a directory handle. See the header
# of sys_proc.c for why fexecve was not the answer either.

sys_proc fork

sys_proc fchdir
sys_proc pipe
sys_proc dup2
sys_proc fcntl

# ---- compiler lowerings, marked optional with a trailing "?" ----
#
# These are not dependencies this program asked for. A C compiler is free to
# rewrite a call whose format string has no conversions: clang turns
# printf("done") into puts and fprintf(stderr, "done") into fwrite, while gcc
# under _FORTIFY_SOURCE turns the same calls into __printf_chk and
# __fprintf_chk and lowers neither. Which set appears is a property of the
# toolchain, so pinning either would make the audit fail on the platform that
# chose the other -- the exact shape of defect this project has hit four times
# now.
#
# "?" means permitted, not required. The forward rule is unchanged: a symbol
# still has to be on this list to be allowed at all, so a genuine fwrite in a
# unit that has no business writing anything is still a finding. Only the
# "nothing references this" rule skips them, because on half the toolchains
# nothing will.
#
# Every one of these is a lowering of a call already listed above for the same
# unit. A lowering of something NOT already listed would be a real dependency
# wearing a disguise, and does not belong here.
main puts ?
main fputs ?
main fwrite ?
main stdout ?
broker puts ?
broker fputs ?
broker fwrite ?
child fputs ?
child fwrite ?
ops fputs ?
